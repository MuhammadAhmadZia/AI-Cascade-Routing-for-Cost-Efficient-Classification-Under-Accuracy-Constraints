# AI cascade routing for cost-efficient classification under accuracy constraints

Replication package for the paper of the same name, submitted to *Artificial
Intelligence and Applications*.

A small language model answers first; items it is unsure about escalate to a
large one. The question is what that saves once you hold accuracy to a stated
floor. Across four classification tasks and two sizes of small model, savings at
a 95% retention floor run from **13.8% to 73.7%**, and they rise with the small
model's own accuracy rather than with anything about the router.

---

## Headline results

| Dataset | Labels | Small model | Small acc | Large acc | Escalated | Saving |
|---|---|---|---|---|---|---|
| CFPB | 10 | Qwen3-1.7B | 0.296 | 0.757 | 81.4% | 13.8% |
| CFPB | 10 | Qwen3-4B | 0.499 | 0.757 | 55.8% | 32.7% |
| Banking77 | 77 | Qwen3-1.7B | 0.498 | 0.680 | 55.8% | 39.4% |
| Banking77 | 77 | Qwen3-4B | 0.605 | 0.680 | 18.1% | 63.7% |
| LEDGAR | 99 | Qwen3-1.7B | 0.278 | 0.586 | 76.8% | 20.4% |
| LEDGAR | 99 | Qwen3-4B | 0.480 | 0.586 | 39.8% | 46.7% |
| CLINC150 | 149 | Qwen3-1.7B | 0.560 | 0.788 | 43.8% | 50.1% |
| CLINC150 | 149 | Qwen3-4B | 0.724 | 0.788 | 5.2% | 73.7% |

Large tier is Qwen3-14B at 4-bit throughout. Escalation and saving are measured
at the cheapest operating point that retains 95% of large-model accuracy.

Three things are worth reading off this table rather than from the correlation:

**The router did not get better.** Error-detection AUROC moves by at most 0.025
between the two small models, and by 0.004 on CFPB. What changes is how much
needs escalating, which falls by 26 to 39 points. The better cascade has less
work to hand upward, not a cleverer rule for handing it.

**Confidence is well-ordered and badly calibrated.** AUROC runs 0.712 to 0.847
while expected calibration error runs 0.233 to 0.377. A router needs the
ordering, not the absolute level, because the threshold is fitted on data
anyway.

**A sizeable part of each workload is unreachable.** Between 17% and 38% of
items defeat both tiers, so no escalation policy can fix them. That bounds what
any router could achieve and is reported rather than hidden.

## Quick start

```bash
git clone https://github.com/USER/slm-cascade-routing
cd slm-cascade-routing
pip install -r requirements.txt

pytest -q                      # 14 tests, no GPU, a few seconds
python -m src.figures          # regenerate all four figures from results/
```

The published tables ship in `results/`, so figures and the statistical
reanalysis reproduce with no GPU and no downloads.

To rerun the experiments end to end:

```bash
python scripts/00_freeze_datasets.py   # once; writes checksummed samples
bash scripts/01_run_small_models.sh    # GPU, resumable
bash scripts/02_run_large_model.sh     # GPU, resumable, separate process
bash scripts/03_analyse.sh             # CPU, seconds
```

On Colab, `notebooks/01_colab_runner.ipynb` does all of this with results
persisted to Google Drive. Start with `notebooks/00_smoke_test.ipynb`: one
dataset, 200 instances, under an hour, and it will tell you whether the pipeline
is sound before you commit roughly ten GPU-hours to the full grid.

## Method, and the parts that are easy to get wrong

**Prediction is by label likelihood, not free generation.** Every candidate
label is scored against the prompt, which removes parse failures and yields a
full distribution over the label set from the same pass. The three confidence
signals therefore cost nothing extra.

**The prefix cache must be cropped between labels.** A `DynamicCache` is mutated
in place by every forward pass. Reuse it without cropping and label 2 is scored
conditioned on label 1's tokens, label 3 on labels 1 and 2, and so on. The
resulting distribution looks entirely plausible and is wrong, with no warning
anywhere. `crop_cache` in `src/scoring.py` is the fix, and it is the single
easiest thing to omit when reimplementing this.

**Signals are oriented so higher means more confident.** Escalation fires below
a threshold, so a sign error silently inverts the router while still producing
plausible output. `test_inverted_confidence_falls_below_random` is the guard.

**The small tier is charged on every item, escalated ones included,** and the
charge covers the prompt prefix plus every scored label continuation. Charging
only the prompt would understate the cheap tier by roughly a quarter on a
77-label task, and understating the cheap tier is exactly the accounting error
that inflates reported savings.

**Thinking mode is disabled.** Qwen3 enables a reasoning block by default, which
would open a `<think>` span precisely where the label distribution is read.

## Cost model and its limits

```
C(E) = c_s * n + c_l * |E|          c = parameters x tokens processed
```

The ratio `k = c_l / c_s` is 8.2 for the 1.7B cascade and 3.5 for the 4B
cascade. The proxy is linear in processed tokens, so it omits the quadratic
attention term, key-value cache traffic, and everything that depends on
hardware, batching and kernel implementation.

Two things limit the damage. Both tiers run the same prompts through the same
procedure on the same accelerator, so the omitted terms enter both sides, and
the analysis turns on the ratio rather than either absolute cost.
`results/cost_ratio_sensitivity.csv` then varies that ratio directly.

**These are proxy compute savings.** They are not measured latency, energy or
money, and the paper does not claim otherwise.

## Why a retention floor rather than cost per correct decision

Minimising cost per correct decision, with no constraint, gives a degenerate
answer at any realistic cost ratio. Writing `F(r)` for cost per correct decision
at escalation rate `r` and `g(r)` for the accuracy it buys:

```
F(r) = c_s n (1 + k r) / (a_s + g(r))
```

The derivative at the origin is negative only when `k a_s < g'(0)`. Each
escalated item can flip at most one answer, so `g'(0) <= 1`, giving the
necessary condition `k < 1 / a_s`. It is necessary, not sufficient, and going
from a non-negative derivative at the origin to the absence of any interior
minimum needs `g` concave, which is what a sensible escalation order produces
since the items with most to gain go first.

The condition fails in all eight published configurations. The 1.7B cascade runs
at `k = 8.2` against `1 / a_s` between 1.79 and 3.60; the 4B cascade runs at
`k = 3.5` against values between 1.38 and 2.08. The closest case still leaves a
factor of 1.7. Unconstrained, the objective says never escalate, which is
arithmetically correct and practically useless. Price-based accounting makes it
worse, since commercial price ratios usually exceed the parameter ratio.

Both claims are tested: `test_interior_minimum_condition_fails_for_every_published_config`
and `test_concavity_makes_the_condition_sufficient`.

## On the correlation

Savings track small-model accuracy with a pooled r of 0.96 across eight points.
Eight points with two per dataset are not eight independent observations, so
`results/scaling_reanalysis.json` reports the checks that matter:

- **Cluster bootstrap** resampling whole datasets, which respects the pairing:
  r in [0.88, 0.99] over 20,000 draws
- **Leave one dataset out**: r stays between 0.921 and 0.975
- **Within-dataset movement**: the 4B tier raises savings on all four datasets,
  by 0.189 to 0.263, mean 0.233
- **Honest limit**: four datasets give a one-sided sign test of 0.0625, so the
  direction is consistent but not conclusive at conventional levels
- **Local slope varies 0.93 to 2.27**, a factor of 2.4

The relationship is monotone and steep. It is not linear with a coefficient that
would transfer to an unseen task, and the paper says so.

## Reproducibility notes

Exact versions are in `environment.txt`: torch 2.11.0+cu130, transformers
5.17.0, bitsandbytes 0.50.2, on a single Tesla T4.

**Pin transformers to 5.17.** Passing a positive value to `DynamicCache.crop` is
deprecated and removed in 5.18. `src/scoring.py` uses the documented call; on
5.18 and later, pass a negative count instead.

Everything is seeded at 0: sampling, bootstrap resampling, cross-fitting folds,
and the random-escalation baseline. Inference is greedy label scoring with no
sampling, so small floating-point differences across driver or kernel versions
are the only expected source of variation.

Sample sizes differ by dataset, 1000 for CFPB and Banking77, 500 for LEDGAR and
CLINC150. Every table reports per-dataset n.

## What is not here

The raw per-item prediction tables and `(N, K)` score matrices are large and are
released as a separate archive rather than in git. `src/run_inference.py`
regenerates them, and `data/predictions/` is where they belong.

The score matrices are worth keeping. With them on disk, any later question
about scoring rules, calibration or alternative confidence signals is answered
without touching a GPU.
